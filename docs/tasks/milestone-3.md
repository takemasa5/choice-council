# M3 詳細仕様: 専門家選定、専門家コメント並列生成

状態: `決定`

## 目的と対象範囲

M3 では、前提整理でファシリテーターが提示した専門家ロール候補をユーザーが編集・確定し、確定済み専門家ごとの初回コメントを並列生成する。全コメントをカードUIで表示し、M4 のグループチャットを開始できる状態へ引き渡す。

対象に含めるものは、専門家候補の編集、最大5件の確定、初回専門家コメントの全件並列生成、`expert_selection` から `deliberation` への遷移、「意見交換をはじめる」操作である。

M3 では、独立したセッションメモ更新、一時保存、割り込み、終了メモ生成、外部調査を実装しない。

## 前提と遷移

M3 は、M2 のファシリテーター応答が `user_question: null`、`next_action: request_experts`、1件以上の `expert_requests` を返した場合に開始できる。

1. ユーザーが `premise` で「専門家選定へ進む」を選ぶ。
2. アプリは `expert_selection` に遷移し、`expert_requests` を専門家候補として表示する。
3. ユーザーが候補を編集して確定する、またはおまかせで確定する。
4. アプリは `deliberation` に遷移し、確定済み専門家のコメントを並列生成する。
5. 全コメントが成功した場合、アプリはコメントカードと「意見交換をはじめる」操作を表示する。
6. ユーザーが開始操作を選んだ場合、アプリは M4 の `group_chat` に遷移する。

## 専門家候補の表示と編集

各候補は、`role_name`（専門家）、`viewpoint`（観点）、`request`（依頼）の入力欄として表示する。候補には、追加、外す、入れ替えの操作を提供する。

- 追加: 空の候補行を末尾に追加する。
- 外す: 対象の候補行を削除する。
- 入れ替え: 対象の候補行の3項目を空にし、ユーザーが別の専門家を入力できるようにする。
- このまま進める: 表示中の候補内容を確定する。
- おまかせで進める: ファシリテーターが最初に提示した候補を、編集内容を用いずにそのまま確定する。

確定する各候補は、3項目すべてがtrim後に空であってはならない。1項目でも入力されている候補行に空欄がある場合は確定できず、`追加した専門家ロールの役割名、観点、依頼をすべて入力してください。` と表示する。確定対象が0件の場合は、`確定する専門家ロールを1件以上入力してください。` と表示する。

3項目すべてが空の候補行は、編集中の空行として確定対象から除外する。ただし、候補行としては上限数に数える。

専門家数はシステム設定で制限し、M3の初期上限は5件とする。候補行が5件に達した場合、追加操作を無効化し、「専門家を追加する」ボタンを押せない状態にする。候補行数が上限未満に戻った場合だけ、追加ボタンを再び有効化する。同じ `role_name` と `viewpoint` の組み合わせは重複してよい。

確定後は、確定済みの専門家ロールを一覧表示し、専門家コメント生成操作を提供する。確定済みの候補を変更する場合は、専門家選定画面で再度確定する。確定済み専門家の変更後は、先に生成した専門家コメントおよびファシリテーター整理を破棄する。

## 専門家コメントの並列生成

専門家コメントの生成は、確定済み専門家が1件以上ある場合だけ開始できる。アプリは生成中であることを表示し、重複送信を防ぐため、生成開始操作および候補の編集操作を無効化する。

アプリは確定済み専門家ごとに `POST /api/expert/comment` を並列で呼び出す。全リクエストが成功するまで、個別コメントを表示しない。すべてが成功した場合だけ、確定済み専門家と同じ順序でコメントを表示する。

1件でも失敗した場合は、全件失敗として扱う。成功したコメントを表示、保持、メモ更新APIへの送信に用いてはならない。すべてのリクエストの完了後にエラーを表示し、ユーザーが明示的に再試行できる状態に戻す。再試行では、確定済み専門家の全件を再度並列生成する。

## グループチャットへの引き渡し

全専門家コメントが成功した場合、アプリはコメントカードの下に「意見交換をはじめる」操作を表示する。この段階ではファシリテーター整理APIを呼び出してはならない。

ユーザーが開始操作を選んだ場合の `group_chat` への遷移、ファシリテーターの最初の進行、会話履歴の管理は M4 の対象とする。

## エラーと対象外

初回専門家コメントAPIの入力不正、API key未設定、LLM API呼び出し失敗、構造化出力の検証失敗の扱いは、`docs/tasks/milestone-2.md#API エラー表示` および `docs/api/schemas.md#バリデーション` に従う。

M3では `POST /api/session-memo/update` を呼び出さない。セッションメモの更新、保存、更新完了通知はM4で扱う。

## Acceptance Criteria

- Given 前提整理の応答が専門家候補を返しているとき、When ユーザーが専門家選定へ進むなら、Then アプリは `expert_selection` に遷移し、候補ごとに専門家、観点、依頼を編集できる。
- Given 専門家候補が5件あるとき、When 専門家選定画面を表示するなら、Then アプリは追加操作と「専門家を追加する」ボタンを無効化する。
- Given 1項目でも入力された候補行に空欄があるとき、When ユーザーが候補を確定しようとするなら、Then アプリは専門家を確定せず、不足項目を入力するよう表示する。
- Given ユーザーが「おまかせで進める」を選んだとき、When 専門家を確定するなら、Then アプリはファシリテーターが最初に提示した候補を編集内容なしで確定する。
- Given 1〜5件の専門家が確定しているとき、When ユーザーが専門家コメントを生成するなら、Then アプリは各専門家の `POST /api/expert/comment` を並列で呼び出す。
- Given 専門家コメントのいずれかが失敗したとき、When 全リクエストが完了するなら、Then アプリは成功分を表示・保持せず、全件をユーザー操作で再試行できる状態にする。
- Given 全専門家コメントが成功したとき、When アプリがコメントを受け取るなら、Then アプリはコメントカードと「意見交換をはじめる」操作を表示する。
- Given ユーザーが「意見交換をはじめる」を選んだとき、When アプリが遷移するなら、Then アプリは M4 の `group_chat` を開始する。

## 完了条件

- ユーザーが専門家候補を追加、削除、入れ替え、編集して確定できる。
- おまかせ操作で、最初に提示された候補をそのまま確定できる。
- 専門家数の上限が5件としてシステム設定で適用される。
- 確定済み専門家のコメントを全件並列生成できる。
- 一部失敗を含むコメント生成を全件失敗として扱い、ユーザーが全件再試行できる。
- 全コメント表示後、ユーザーが「意見交換をはじめる」を選べる。
- M4 のグループチャットへ必要な初回コメント、確定済み専門家、セッションメモを引き渡せる。
- M3 に対応する API、クライアント状態遷移、並列成功・失敗のテストが成功する。
- `npm run typecheck` と `npm run build` が成功する。
