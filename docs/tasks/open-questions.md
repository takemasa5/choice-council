## M3 からの申し送り

状態: `MVP対象外`

- M3 の `POST /api/facilitator/deliberation` は、相談内容、現在メモ、確定済み専門家、全専門家コメントを毎回リクエストで受け取る。コメント量が増えた場合のコンテキスト長・転送量の課題には、MVPでは対応しない。将来、backend 内でセッションまたは会話履歴を保持する場合は、保存期間、削除、プライバシー、復元、複数リクエスト間の整合性を別途仕様化する。

## M4 への申し送り

状態: `決定`

- M2 では `FacilitatorResponse.memo_updates` を画面表示と前提整理の再送文脈として保持するだけであり、`POST /api/session-memo/update` は呼び出さない。M4 では、フェーズ区切りで独立メモ更新 API を呼ぶタイミング、失敗時の表示・再実行、更新完了通知を実装する。
- M2 の `user_question` は `required: true` に限定する。M4 では、割り込みを含む任意質問（`required: false`）の送信・スキップ・状態遷移を詳細化する。

## 解消済み

次の事項は初期設定で方針を決定済み。

- 技術スタック: TypeScript + React + Node.js + Express。
- 使用する LLM API: OpenAI API。
- M1 のプロンプト範囲: 契約定義のみ。文言調整と品質検証は M2 以降。
- フェーズ遷移: 通常操作として前フェーズへ戻れる。
- 前フェーズへ戻る場合: 確認後、戻り先より後の生成結果を現在セッションから完全に破棄し、戻り先フェーズの入力状態からやり直せる。
- M1 の schema 同期範囲: `docs/` の詳細仕様まで。Zod schema 実装は実装タスクとして扱う。
- JSON schema の厳密さ: 未知フィールド不可、必須文字列と配列要素の空文字不可。
