# M4 詳細仕様: グループチャットとセッションメモ

状態: `決定`

## 目的と対象範囲

M4 では、初回専門家コメントの後にユーザーが開始する `group_chat` を実装する。ファシリテーターが専門家またはユーザーを1人ずつ指名して検討を進め、重要な整理をセッションメモへ反映できる状態を対象とする。

| 区分     | 対象                                                                               |
| -------- | ---------------------------------------------------------------------------------- |
| 状態     | `deliberation → group_chat` の遷移、`group_chat → deliberation` の戻り             |
| 画面     | チャットタイムライン、発言者区別、専門家生成中表示、ユーザー指名時の入力、終了操作 |
| API      | グループチャット開始、専門家のチャット回答、次のファシリテーターターン             |
| 会話制御 | 1人ずつの指名、専門家連続回答の上限、ユーザー指名規則                              |
| メモ     | 重要時の更新、グループチャット開始時点への復元                                     |
| 文脈     | 累積会話要約と直近発言を用いる長い会話の継続                                       |

終了状態の選択と Markdown 終了メモの生成は M5 の対象とする。

M4 の実装では、`src/shared/schemas`、`server/app.ts`、`src/client/` のフェーズ・route・フローを同じ変更で同期する。`group_chat` を有効化する変更と、`direction` および `POST /api/facilitator/deliberation` の削除を別々にリリースしてはならない。

## 前提と遷移

1. M3 が初回専門家コメントを全件表示する。
2. ユーザーが「意見交換をはじめる」を選ぶ。
3. アプリは `group_chat` に遷移し、開始時点の `SessionMemo` を保存する。
4. アプリは `POST /api/facilitator/group-chat/start` を呼び出し、最初の `FacilitatorTurn` を表示する。
5. 指名先が専門家なら、`POST /api/expert/group-chat` を呼び出して回答を表示する。指名先がユーザーなら、回答を待つ。
6. 専門家またはユーザーの回答後、アプリは `POST /api/facilitator/group-chat/next` を呼び出す。

`group_chat` から `deliberation` に戻る場合は確認を表示する。ユーザーが同意した場合だけ、グループチャット履歴、累積要約、チャット中のメモ更新を破棄し、開始時点のメモへ戻す。初回専門家コメントと確定済み専門家は保持する。

## 会話制御

- ファシリテーターは、各ターンで専門家またはユーザーを1人だけ指名する。
- 指名理由と質問はファシリテーターのチャット発言として表示する。
- 初回専門家コメントは、グループチャットの発言回数に含めない。
- 専門家の連続回答は最大2回とする。2回の専門家回答後の3回目は、必ずユーザーを指名する。
- 発言内容に最も関連する、または最も対立する参加者がユーザーである場合、専門家1回の回答後にユーザーを指名できる。
- ユーザーの自由入力、選択肢回答、「そのまま意見交換を続けて」は、いずれもユーザー意思表示として連続専門家回答数を0へ戻す。
- ファシリテーターの進行・要約・指名理由は、参加者回答数に含めない。

## ユーザー入力と終了操作

ユーザーが指名された場合だけ、質問、選択肢、自由入力欄を表示する。選択肢は2件以上とし、「その他」と「そのまま意見交換を続けて」を必ず含める。

「検討を終える」は常時表示する。M4 では、終了確認ダイアログを表示してユーザーの確定を待つところまでを扱う。終了状態の選択と終了メモの生成は M5 で実装する。

## セッションメモと会話文脈

ファシリテーターは、判断軸、選択肢、対立点、未確認事項に重要な変化がある場合だけ `SessionMemo` を更新する。更新時は「メモを更新しました」と表示する。毎発言でメモを更新してはならない。

画面は現セッション中の全チャット履歴を保持・表示する。LLM 呼び出しには、全履歴を毎回渡さず、累積会話要約、最新のセッションメモ、直近の発言群を渡す。会話ターン数の上限は設けない。

同名・同観点の専門家を複数確定できるため、グループチャット内の専門家は表示名とは別に一意な `participantId` で対応付ける。

## UI

- 初回専門家コメントのカードUIは M3 のまま維持する。
- グループチャットでは、ファシリテーター、専門家、ユーザーを見分けられるメッセージ表示にする。
- 相談内容の入力欄と相談原文は `expert_selection` 以降に表示しない。セッションメモの整理済み情報を表示する。
- 本文、カード、チャットの文字を現行より少し小さくし、行間・余白を見直して1画面の情報量を増やす。
- 専門家回答の生成失敗時は、会話状態を進めず、対象の回答だけを再生成できるようにする。

## Acceptance Criteria

- Given 初回専門家コメントが全件表示されているとき、When ユーザーが「意見交換をはじめる」を選ぶなら、Then アプリは `group_chat` に遷移して最初の `FacilitatorTurn` を表示する。
- Given M4 のグループチャットを有効化するとき、When 共有schema、サーバーroute、クライアントフローを更新するなら、Then システムは `group_chat` を一貫して使用し、`direction` と `POST /api/facilitator/deliberation` を提供しない。
- While `group_chat` にいるとき、When ファシリテーターが次の発言者を指定するなら、Then アプリは1人だけを指名し、指名理由と質問を表示する。
- While `group_chat` にいるとき、When `FacilitatorTurn` を検証するなら、Then `requestedSpeaker.speakerType` は `expert` または `user` だけを許可する。
- While 前回のユーザー意思表示以降に専門家が2回回答しているとき、When 次の `FacilitatorTurn` を受け取るなら、Then アプリは専門家を指名する応答を不正として扱う。
- Given ユーザーが指名されているとき、When 入力欄を表示するなら、Then アプリは自由入力、選択肢、「その他」、「そのまま意見交換を続けて」を提供する。
- Given グループチャットから `deliberation` へ戻るとき、When ユーザーが確認に同意するなら、Then アプリはチャット履歴とチャット中のメモ更新を破棄し、グループチャット開始時点のメモへ戻す。
- Given 専門家チャット回答の生成が失敗したとき、When ユーザーが再生成するなら、Then アプリは会話履歴と連続専門家回答数を変えずに同じ対象の回答だけを再生成する。

## Out of Scope

- 終了状態の選択と Markdown 終了メモ生成。
- 過去セッションの永続保存、ログイン、外部調査。
- グループチャットの自動終了やターン数上限。
