# ユーザー体験設計

## 開始画面

開始画面では、相談内容の自由入力を中心に置く。

必須入力は「相談内容」のみとする。ユーザーが考えを整理できていない状態でも開始できるよう、補助項目は任意・折りたたみ表示にする。

| 項目           | 必須 | 表示       |
| -------------- | ---: | ---------- |
| 相談内容       | 必須 | 常時表示   |
| 事実・背景     | 任意 | 折りたたみ |
| 重視したいこと | 任意 | 折りたたみ |
| 不安なこと     | 任意 | 折りたたみ |
| 期待する結果   | 任意 | 折りたたみ |

placeholder 例:

```text
例: 夏休みの家族旅行で、予算を抑えながら子どもも楽しめる行き先を家族で決めたいです。
```

## 画面構成

MVP の画面は、次の 4 エリアで構成する。

| エリア | 内容                                                 |
| ------ | ---------------------------------------------------- |
| 上部   | 現在フェーズ、進行状況                               |
| 中央   | ファシリテーターと専門家コメントのタイムライン       |
| 右側   | セッションメモ、判断軸、未確認事項                   |
| 下部   | 現在フェーズで必要な操作と、必要時のみユーザー入力欄 |

スマートフォンでは、初期状態が閉じたセッションメモ引き出しを表示する。ユーザーが「セッションメモ」を選んだ場合だけ開き、メモ更新時に自動では開かない。

## セッションの基本フロー

1. ユーザーが相談内容を入力する。
2. ファシリテーターが前提を整理する。
3. ファシリテーターが必須の確認質問を1問表示し、ユーザーが回答する。
4. ファシリテーターが専門家ロールを提案する。
5. ユーザーが専門家を承認、追加、削除、入れ替えする。
6. 専門家が個別に短い初回コメントを出す。
7. ユーザーが1案の深掘り、2案の比較、または選択保留を選ぶ。
8. ファシリテーターが、専門家またはユーザーを1人ずつ指名して意見交換を進める。
9. 重要な整理時にセッションメモを更新する。
10. ユーザーが終了状態を選び、終了メモを Markdown で出力する。

## ユーザー入力の方針

初回入力後、`expert_selection` 以降は相談内容の入力欄と相談原文を表示しない。相談の文脈は、セッションメモに表示するテーマ、事実、価値観、不安などの整理済み情報で把握する。

ユーザーに常時入力を求めることはしない。

ファシリテーターが議論の分岐点で必要と判断した場合にのみ質問する。ただし、初回の必須確認質問は常に `premise` で表示・送信する。`premise` の質問は原則として選択肢形式にし、必ず「その他」を含める。「その他」を選ぶと自由入力できる。

## 初回専門家コメントと意見交換

`deliberation` では、確定済み専門家の初回コメントを既存のカードUIで表示する。初回コメントは全件の生成が成功した場合だけ表示し、1件でも失敗した場合は全件を明示的に再試行できる状態にする。

各コメントには、専門家の要約に加えて案名、内容、利点、犠牲にする点、成立条件を構造化して表示する。全コメントの下で、ユーザーは案を選択して「1案を深掘り」「2案を比較」「まだ選ばない」のいずれかを選ぶ。比較開始ボタンは、案をちょうど2件選んだときだけ有効にする。専門家ロールを選択対象にしてはならない。完全な選択がない限り、グループチャットは開始できない。

案名と選択チェックボックスは同じ案カード内に表示し、選択済みと無効状態を視覚的に区別する。選択操作と意見交換開始操作は、デスクトップでは情報密度を保って並べ、狭幅画面や長い文言ではボタン内で折り返すか次行へ配置して横にはみ出さない。

選択は端末内のセッションへ保存・復元する。復元時に初回コメントの具体案、案ID、選択の参照整合性を検証し、旧形式または不整合な保存値は確定済み専門家を残して専門家選定へ戻す。案をチェックしただけの選択途中の状態も、案IDの重複と参照整合性が取れていれば初回コメントを維持して `deliberation` へ復元する。開始失敗時は案選択、確定済み専門家、初回コメントを維持し、開始時と同じリクエストを再送する。ただし案選択を変更した場合は、その再試行対象とエラーを破棄する。`group_chat` から `deliberation` への復帰では案選択を保持し、`expert_selection` へ戻る、または初回コメントを再生成する場合は案選択を破棄する。ユーザーがこの操作を完了するまで、グループチャットのタイムラインとチャット用のユーザー入力欄は表示しない。

意見交換の開始に失敗した場合は、`deliberation` にエラー内容と再試行操作を表示する。この場合は `group_chat` へ遷移せず会話履歴を保存しない。再試行では、確定済み専門家と初回コメントを維持したまま、開始時と同じリクエストを再送する。

`group_chat` では、ファシリテーター、専門家、ユーザーを区別して時系列に表示する。ファシリテーターは、次に誰を指名するか、その理由、質問内容を自身の発言として示す。同時に複数人を指名してはならない。

グループチャットの発言表示は、ファシリテーターを中央寄せの進行カード、専門家を左寄せの発言、ユーザーを右寄せの吹き出しとする。ファシリテーターの表示名は「ファシリテーター」のみとし、「進行役」ラベルは表示しない。専門家は役割名のみを表示し、「専門家」ラベルは表示しない。ユーザーの表示名は「あなた」のみとする。役割の識別は中央・左・右の配置、吹き出し、アバターで維持する。3種類の発言者すべてにアバターを表示し、ファシリテーターとユーザーはそれぞれ固定アバターとする。専門家のアバターは participantId から再現可能に生成し、役割名の先頭1〜2文字と participantId に基づく色に加え、participantId 文字列から直接かつ決定的に導出される非色の短縮識別子を表示する。同名の専門家を含め、専門家は色以外でも区別できるようにする。

専門家が指名された場合は、最新のファシリテーター質問の後に「専門家の回答を生成中」を表示し、回答後にファシリテーターが次の発言者を選ぶ。次の発言者を取得中は、同じ位置に「次の進行を生成中」を表示する。復元後に通信が再開されていない場合も、ユーザーは「専門家回答を再生成する」操作を明示的に選んで回答生成を再開できる。ユーザーが指名された場合だけ、質問、選択肢、自由入力用の textarea を同時に表示する。選択肢は2件以上とし、必ず「そのまま意見交換を続けて」を含め、「その他」は含めない。旧保存セッションの復元時に `userOptions` に「その他」が残っている場合も、その選択肢は表示・送信しない。選択肢を押すと、その選択肢の文言をユーザー回答として直ちに送信する。「そのまま意見交換を続けて」を選んだ場合も、ユーザーの意思表示として扱う。textarea から送信した内容もユーザー回答として扱う。選択肢の文言が長い場合でも、ボタン内で折り返して表示し、レイアウトを崩さない。

初回専門家コメントはグループチャットの発言回数に数えない。チャット開始後、専門家の連続回答は最大2回とし、2回の専門家回答を受け取った後の3回目は必ずユーザーを指名する。発言内容に最も関連する、または最も対立する参加者がユーザーである場合は、専門家1回の回答後にユーザーを指名できる。ファシリテーターの進行、要約、指名理由はこの回数に数えない。

「検討を終える」はユーザーの指名状態にかかわらず常時表示する。LLM 通信中だけは無効化する。選択すると画面内モーダルを表示し、ユーザーは次の終了状態をラジオ選択する。

- 暫定結論
- 判断保留
- 追加調査待ち
- 家族・関係者相談待ち
- 実行計画

キャンセル時は意見交換を続ける。確定時は `SessionMemo.status` を選択値に更新して `final_memo` へ遷移し、終了メモ生成を自動開始する。生成に失敗した場合は `group_chat` へ戻り、`SessionMemo.status` を `in_progress` に戻して終了状態を選び直す。

## 文字サイズと情報密度

現在の画面より本文、カード、チャットの文字を少し小さくし、行間と余白も見直す。可読性を保ちながら、1画面に表示できる情報量を増やす。ヘッダー、フェーズ表示、主要ボタン、カード内の余白もこの方針にそろえる。

## 通信状態

LLM または API への通信中は、`group_chat` 以外のフェーズでは上部のフェーズ表示の横にアニメーション付きの「通信中」インジケータを表示する。`group_chat` では、スクロールしても現在の会話の進行を確認しやすいよう、最新のファシリテーター質問と回答操作の間に状態別の表示を出す。`group_chat` 中は上部のインジケータを表示しない。

インジケータは画面上の通信状態を示す共通の表示であり、個別操作のボタン文言による進捗表示を置き換えない。スクリーンリーダーへはステータスとして通知する。

## 専門家間のディベート

`group_chat` は開始時の案選択を必ず起点にする。深掘りでは提案者の根拠を検証し、他専門家が具体的な反論・代替・成立条件を示す。比較では選んだ2案のトレードオフを検討する。保留では案を早期に脱落させず、比較軸を整理する。専門家回答は、初回コメントの繰り返しではなく、直前の他専門家の主張に対する応答として進める。ファシリテーターは、論点の対立または補完関係がある場合、次の専門家に相手の主張を明示して質問する。

連続して専門家を指名する場合、確定済み専門家が2人以上なら直前に発言した専門家とは別の専門家を指名する。専門家は、賛成・留保・反論のいずれかを明確にし、その理由または条件を述べる。ファシリテーターはこの応酬を要約し、必要に応じてユーザーへ判断軸を確認する。
