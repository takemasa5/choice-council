# ユーザー体験設計

## 開始画面

開始画面では、相談内容の自由入力を中心に置く。

必須入力は「相談内容」のみとする。ユーザーが考えを整理できていない状態でも開始できるよう、補助項目は任意・折りたたみ表示にする。

| 項目           | 必須 | 表示       |
| -------------- | ---: | ---------- |
| 相談内容       | 必須 | 常時表示   |
| 事実・背景     | 任意 | 折りたたみ |
| 重視したいこと | 任意 | 折りたたみ |
| 不安なこと     | 任意 | 折りたたみ |
| 期待する結果   | 任意 | 折りたたみ |

placeholder 例:

```text
例: 小5の娘の中学受験をするか迷っています。本人の負担と将来の選択肢のどちらを重視すべきか整理したいです。
```

## 画面構成

MVP の画面は、次の 4 エリアで構成する。

| エリア | 内容                                                 |
| ------ | ---------------------------------------------------- |
| 上部   | 現在フェーズ、進行状況                               |
| 中央   | ファシリテーターと専門家コメントのタイムライン       |
| 右側   | セッションメモ、判断軸、未確認事項                   |
| 下部   | 現在フェーズで必要な操作と、必要時のみユーザー入力欄 |

スマートフォンでは、初期状態が閉じたセッションメモ引き出しを表示する。ユーザーが「セッションメモ」を選んだ場合だけ開き、メモ更新時に自動では開かない。

## セッションの基本フロー

1. ユーザーが相談内容を入力する。
2. ファシリテーターが前提を整理する。
3. ファシリテーターが必須の確認質問を1問表示し、ユーザーが回答する。
4. ファシリテーターが専門家ロールを提案する。
5. ユーザーが専門家を承認、追加、削除、入れ替えする。
6. 専門家が個別に短い初回コメントを出す。
7. ユーザーが「意見交換をはじめる」を選ぶ。
8. ファシリテーターが、専門家またはユーザーを1人ずつ指名して意見交換を進める。
9. 重要な整理時にセッションメモを更新する。
10. ユーザーが終了状態を選び、終了メモを Markdown で出力する。

## ユーザー入力の方針

初回入力後、`expert_selection` 以降は相談内容の入力欄と相談原文を表示しない。相談の文脈は、セッションメモに表示するテーマ、事実、価値観、不安などの整理済み情報で把握する。

ユーザーに常時入力を求めることはしない。

ファシリテーターが議論の分岐点で必要と判断した場合にのみ質問する。ただし、初回の必須確認質問は常に `premise` で表示・送信する。質問は原則として選択肢形式にし、必ず「その他」を含める。「その他」を選ぶと自由入力できる。

## 初回専門家コメントと意見交換

`deliberation` では、確定済み専門家の初回コメントを既存のカードUIで表示する。初回コメントは全件の生成が成功した場合だけ表示し、1件でも失敗した場合は全件を明示的に再試行できる状態にする。

全コメントの下に「意見交換をはじめる」ボタンを置く。ユーザーがこのボタンを押すまで、グループチャットのタイムラインとチャット用のユーザー入力欄は表示しない。

意見交換の開始に失敗した場合は、`deliberation` にエラー内容と再試行操作を表示する。この場合は `group_chat` へ遷移せず会話履歴を保存しない。再試行では、確定済み専門家と初回コメントを維持したまま、開始時と同じリクエストを再送する。

`group_chat` では、ファシリテーター、専門家、ユーザーを区別して時系列に表示する。ファシリテーターは、次に誰を指名するか、その理由、質問内容を自身の発言として示す。同時に複数人を指名してはならない。

専門家が指名された場合は、「意見交換」見出しの横に回答生成中の表示を出し、回答後にファシリテーターが次の発言者を選ぶ。ユーザーが指名された場合だけ、質問、選択肢、自由入力欄を表示する。選択肢には必ず「その他」と「そのまま意見交換を続けて」を含める。後者を選んだ場合も、ユーザーの意思表示として扱う。

初回専門家コメントはグループチャットの発言回数に数えない。チャット開始後、専門家の連続回答は最大2回とし、2回の専門家回答を受け取った後の3回目は必ずユーザーを指名する。発言内容に最も関連する、または最も対立する参加者がユーザーである場合は、専門家1回の回答後にユーザーを指名できる。ファシリテーターの進行、要約、指名理由はこの回数に数えない。

「検討を終える」はユーザーの指名状態にかかわらず常時表示する。LLM 通信中だけは無効化する。選択すると画面内モーダルを表示し、ユーザーは次の終了状態をラジオ選択する。

- 暫定結論
- 判断保留
- 追加調査待ち
- 家族・関係者相談待ち
- 実行計画

キャンセル時は意見交換を続ける。確定時は `SessionMemo.status` を選択値に更新して `final_memo` へ遷移し、終了メモ生成を自動開始する。生成に失敗した場合は `group_chat` へ戻り、`SessionMemo.status` を `in_progress` に戻して終了状態を選び直す。

## 文字サイズと情報密度

現在の画面より本文、カード、チャットの文字を少し小さくし、行間と余白も見直す。可読性を保ちながら、1画面に表示できる情報量を増やす。
