# ユーザー体験設計

## 開始画面

開始画面では、相談内容の自由入力を中心に置く。

必須入力は「相談内容」のみとする。ユーザーが考えを整理できていない状態でも開始できるよう、補助項目は任意・折りたたみ表示にする。

| 項目           | 必須 | 表示       |
| -------------- | ---: | ---------- |
| 相談内容       | 必須 | 常時表示   |
| 事実・背景     | 任意 | 折りたたみ |
| 重視したいこと | 任意 | 折りたたみ |
| 不安なこと     | 任意 | 折りたたみ |
| 期待する結果   | 任意 | 折りたたみ |

placeholder 例:

```text
例: 小5の娘の中学受験をするか迷っています。本人の負担と将来の選択肢のどちらを重視すべきか整理したいです。
```

## 画面構成

MVP の画面は、次の 4 エリアで構成する。

| エリア | 内容                                           |
| ------ | ---------------------------------------------- |
| 上部   | 現在フェーズ、進行状況                         |
| 中央   | ファシリテーターと専門家コメントのタイムライン |
| 右側   | セッションメモ、判断軸、未確認事項             |
| 下部   | ユーザー入力欄、「ちょっと待って」ボタン       |

スマートフォンでは、セッションメモをタブまたは引き出しで表示する。

## セッションの基本フロー

1. ユーザーが相談内容を入力する。
2. ファシリテーターが前提を整理する。
3. 情報不足が大きい場合のみ、ユーザーに 1〜2 問確認する。
4. ファシリテーターが専門家ロールを提案する。
5. ユーザーが専門家を承認、追加、削除、入れ替えする。
6. 専門家が個別に短いコメントを出す。
7. ファシリテーターがコメントを整理する。
8. 必要に応じて、ユーザーに選択肢つきで確認する。
9. フェーズ区切りでセッションメモを更新する。
10. セッション終了時に、終了メモを Markdown で出力する。

## ユーザー入力の方針

初回入力後、ユーザーに常時入力を求めることはしない。

ファシリテーターが議論の分岐点で必要と判断した場合にのみ質問する。質問は原則として選択肢形式にし、必ず「その他」を含める。「その他」を選ぶと自由入力できる。

## 「ちょっと待って」ボタン

MVP では、割り込み用のボタンを 1 つ用意する。

ユーザーがボタンを押した場合、実行中の LLM 処理は即時キャンセルせず、次の区切りで停止する。画面には「次の区切りで止めます」と表示する。

停止後、ファシリテーターは次の選択肢を提示する。

- 前提を修正したい。
- この論点を深掘りしたい。
- 外部情報を調べたい。
- 別の選択肢を追加したい。
- いったんまとめたい。
- その他。
